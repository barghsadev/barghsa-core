# One-container Liara staging

`barghsa-stg` runs Nginx, web, API, worker, PostgreSQL 18 with pgvector,
Redis, SeaweedFS S3, and ClamAV in one Docker image. It requires exactly one
Liara instance and a persistent disk mounted at `/data`. The image refuses to
start without the disk. All data services bind to localhost; Nginx exposes
only port 8080.

## Liara setup

1. Keep `barghsa-stg` as a **Docker** app with **one replica**. Allocate enough
   RAM for ClamAV plus the app stack; start with at least 8 GiB and adjust
   based on actual use. Attach `app.barghsa.com` and `s3.barghsa.com` to this
   app. The latter host routes to the built-in S3 service.
2. Create a Liara disk, for example `barghsa-data`, large enough for the
   PostgreSQL database, Redis AOF, object uploads, and antivirus signatures.
   Disk resizing and backups are separate operations.
3. Set these **Liara app environment variables**. Generate new random values;
   do not commit or paste them in tickets:

   | Variable | Purpose |
   | --- | --- |
   | `POSTGRES_PASSWORD` | Local database user password |
   | `S3_ACCESS_KEY_ID` | Local S3 access key |
   | `S3_SECRET_ACCESS_KEY` | Local S3 secret key |
   | `AUTH_DELIVERY_ENCRYPTION_KEY` | Existing app encryption secret |

   Configure any other required app integrations (payment, SMS, email) in the
   same Liara environment. `DATABASE_URL`, `PGDIRECT_URL`, and `REDIS_URL` are
   generated by the entrypoint for localhost. The image supplies default S3,
   ClamAV, and public URL settings. Override the public URLs only if the
   actual domains differ.

4. Deploy from a machine with Docker and the authenticated Liara CLI:

   ```bash
   LIARA_DISK_NAME=barghsa-data deploy/single/deploy.sh deploy
   ```

   `deploy/single/deploy.sh build` builds a local `barghsa-stg:local` image
   without changing Liara. The script compiles the monorepo locally for
   `linux/amd64`, archives runtime output, and sends a small runtime build
   context to Liara. No package install is needed on Liara's builder.

## Startup and operations

Startup initializes PostgreSQL, Redis, SeaweedFS, and ClamAV on `/data`, then
runs database migrations before starting the API, worker, web, and Nginx.
The Docker health check checks the web, API readiness, and worker readiness.
If a required process exits, the whole container exits for Liara to restart.

This is a staging arrangement. A single app restart interrupts every service.
Keep one replica: simultaneous containers would race on the same PostgreSQL
directory and S3 data. Set up off-app backups before treating data as durable;
the Liara disk alone is not a backup. Preserve the `/data` disk when deploying
new images.
