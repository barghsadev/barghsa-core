# Electricity history filters

Canonical work: connected adoption of `07-ui-ux-design.md#T-07.18.02.01` and `.02` for status/date controls, the text portion of `.03`, URL persistence from `.04`, and `07-ui-ux-design.md#T-07.18.01.04` for sorting on the customer electricity order list in `03-core-business.md#T-03.07.04.01`. Other lists, remaining filter types and the full list framework remain open.

Electricity history now shares the status, date, debounced search and sort controls used by saving, solar and consultation histories. Customers can search order, current invoice or contract references, select several commercial statuses, use localized submission date presets or custom dates, and sort newest or oldest first. All selections stay in the URL, compose with each other and the existing In progress view, survive reload and Back, and reset accumulated pages and cursors. Date controls use the saved account timezone, Jalali or Gregorian calendar and inclusive end-day selection. Payment, contract and correction next-action links remain available. The page loads lazily, displays references with RTL isolation and wraps on mobile.

The API validates statuses against the same shared lifecycle allowlist used by its state machine. Unsubmitted drafts remain outside history. Bound, escaped reference search and included/excluded UTC bounds apply to both cursor lookup and row selection before the existing 50-row page limit. Both sort directions order by submission timestamp and UUID. Current invoice joins retain invoice replacement behavior and financial status derivation. Permission/session checks remain in place, and mismatched or unauthorized cursors are rejected. The OpenAPI contract documents the optional filters and sort allowlist.
