# Customer payment and receipt form validation, October 3, 2026

## Scope and result

This batch adopts `07-ui-ux-design.md#T-07.10.01.02`, `.01.04`, `.01.05` and `.01.06` together across online wallet top-up, wallet bank-receipt top-up and invoice bank-receipt submission. Global adoption remains open for the other product forms.

All three forms use shared React Hook Form/Zod validation, touched-field correction, localized linked errors, first-invalid-field focus and a top-of-form Alert for generic failures. Draft amounts, dates, references, bank names, notes and selected files survive review/submission failures. A synchronous lock covers asynchronous validation; submission controls announce busy state, show a reduced-motion-aware spinner and stay locked through the reviewed operation. Profile changes clear the previous financial draft; obsolete upload/review/submit responses cannot open a new confirmation, redirect or refresh the new profile.

Receipt checks reuse the existing exact-int8 amount, calendar, bounded reference/bank/note and file rules. Persian/Arabic digits normalize without converting receipt IRR through Number. Online amounts additionally require a safe positive decimal integer within the current advertised ceiling; server-enforced limit changes update the hint and focus the retained amount. Review hashes, idempotency keys, captured retries, gateway URL checks, attachment verification, Pending/Submitted states and staff-only credit/settlement remain.

Receipt endpoints add safe public `error.fields` metadata for editable fields, including mapping `attachmentKey` to the file input. Protected hash/idempotency or unknown schema fields retain generic parse errors. Metadata never supplies rendered server copy or submitted values. Existing access/session checks, transaction locks, ledger/attachment claims and audits remain; malformed inputs do not claim the upload or write money. No migration or dependency changes.

Each form owns one uploaded-file cache. Review/field/network failures reuse the same verified attachment unless the server rejects that attachment; rejection then discards only the cached key and reuploads the retained File on the next attempt. The redundant hook cache is removed, fixing the browser-observed reuse of a rejected key.

The shared form hook also accepts an asynchronous schema factory with safe, localized load-failure feedback and retained values. The finance schema module loads on the first validation interaction. Zod Mini and the shared domain parsers provide field issues without a new dependency. All 73 previous route/interaction budgets remain unchanged; a separate 20 KB validation interaction budget is added. Final wallet initialization is **289.73 KB / 300 KB**, validation **16.68 KB / 20 KB**, dashboard **291.07 KB / 300 KB**. No automatically rendered UI is excluded from the cold-page measurement.
