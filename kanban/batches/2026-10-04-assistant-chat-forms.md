## Behavior and review

Both forms reuse deferred shared validation, owned Persian/English feedback, touched-field correction, first-error focus, submission indicators and synchronous guards. Questions retain the API's trimmed 1–1000-character limit; admin messages retain 1–4000. Admin submissions validate the currently enabled agent and known preview slot. Validation loading or failure preserves entries and cannot send a request. API feedback exposes only the owning fields, without submitted values, unknown internal fields or validator prose. Staff authorization precedes feedback; versioned snake-case API validation retains its existing contract.

Drafts clear only after HTTP 200 and a valid answer. Failed or malformed responses preserve the captured request and its exact request ID for retry. New submissions stay blocked while an uncertain request awaits retry. The customer can explicitly return to editing the preserved question; staff can explicitly start a new conversation or select another context. Message text stays locked during inference so a late success cannot erase a newer draft. Submission locking suppresses competing blur validation. Owned API feedback remains visible until its field changes or is resubmitted, even if a prior local resolver completes later. Duplicate native/programmatic submits and retry clicks cannot produce concurrent calls.

Customer answers validate source shape, attribution and quota before publishing. Optional legacy policy/time metadata remains explicitly unavailable. Admin answers also validate the conversation UUID, source/attribution agreement, public policy results, tokens, latency and quota, including the existing conversation ID for follow-up messages. Availability reads reject malformed profile/slot contracts. Contract discriminants must be strings; arrays that stringify to known identifiers are rejected. Reply text remains ordinary escaped React content. Existing backend retrieval, policy enforcement, request replay, auditing and rate limits are retained.

HTTP 429 reads the existing Retry-After contract and presents a localized countdown that blocks new sends and captured retries. It does not invent a cooldown when the header is absent or invalid. Profile/slot withdrawal and removed or disabled agents cancel outstanding work and ignore late replies. Authorization denial erases private history and input, locks the affected conversation and uses the admin page's permission boundary. Customer account status continues to read the dashboard directly, with its existing access flags and profile check; account data never enters inference requests.

Quotas, source/policy counts, token counts, latency and visible account amounts use the published numeral preference independently of language. Known policy application states have bilingual labels. Review repaired admin focus after validation unlock and made API-owned feedback survive local resolver completion until edit or resubmit. Mobile Safari tracing found that blurring the grown textarea restored page scroll and moved Send before mouseup; preserving textarea focus through mousedown keeps the tap stable and preserves standard submit validation. Temporary diagnostic instrumentation was removed.

No dependency, migration, endpoint path or CI-setting change is needed. Deploy the API with or before the frontend for owned field feedback. Streaming, AI write tools/confirmations, complete response metadata (including total token metrics and matched rule detail), reusable message components and remaining shared-form adoption stay separate.
