# AI audit foundation and preview integration batch

Task: `05-notifications-documents-ai.md#T-05.22.03`, implemented for the
currently available admin test-chat inference path.

Migration 0214 creates `ai_audit_log` with the task's identity, actor,
profile, tool, redacted input/output, authorization, confirmation, correlation,
token, latency and timestamp fields. Database triggers reject updates, deletes
and truncation, leaving audit records append-only. Identity values are snapshots
so account or session cleanup cannot erase the record.

The admin test-chat endpoint appends a row for each authenticated attempt:
staff permission denial, invalid payload, model/service failure or success.
The writer limits payload size and applies the existing sensitive-value
redactor before persistence. A successful preview waits for its audit insert;
if storage fails, the endpoint does not claim success. Replayed requests also
produce a new audit event. The request correlation ID is preserved.

Production chat slots and tool actions do not yet exist. They must call this
writer with their active profile, authorization and confirmation decisions.
Requests rejected before the controller by session authentication are outside
this endpoint's audit path. The pattern redactor cannot guarantee removal of
unrecognized secrets.

Validation: migrated PostgreSQL HTTP tests verify the records and database
immutability; API/root typecheck, build, lint, formatting, OpenAPI contract,
database snapshot and kanban validation.
