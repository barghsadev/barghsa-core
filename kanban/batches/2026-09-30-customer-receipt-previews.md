# Customer receipt previews and matched invoice context

Canonical work: completes the remaining receipt-image and matched-invoice sections of `07-ui-ux-design.md#T-07.18.03.03`, composing the existing E-04 customer invoice/receipt detail. Together with the preceding receipt-history batch, the pattern has the specified list columns, receipt preview, deposit metadata, matched invoice and verification timeline. This does not complete the broader ListPage framework, filter drawer/global Apply, other domain patterns or staff adoption.

A receipt selected from the cross-invoice history opens its preview on the matching invoice. Other receipts stay collapsed until explicitly opened. The preview displays the receipt image or first PDF page, explains how to open all pages, has a localized accessible description, and offers retry and the existing original-attachment link when unavailable. Each receipt explicitly identifies and links its invoice alongside amount, bank, tracking reference, deposit date, customer note and rejection reason. Verification timelines retain recorded states, account-timezone timestamps and historical-time explanations; their accessible region names now distinguish receipt IDs on invoices with multiple receipts. Receipt filter removal actions now replace the localized filter placeholder with the actual status name.

The new authenticated endpoint serves PNG bytes from the same origin with private/no-store and nosniff headers. It validates invoice/receipt IDs, checks current session/profile/agent authority and the owning non-draft invoice, and reads MIME information only from the receipt's immutable storage record. It does not expose a signed storage URL for inline viewing or relax CSP. The original attachment endpoint remains available. Older receipts missing immutable MIME metadata and unavailable/corrupt sources return a controlled preview-unavailable response.

The existing document renderer and derivative cache are shared rather than duplicated. PNG/JPEG/WebP and the first PDF page become a bounded PNG; source streams are capped at 15 MiB, image decoding at 25 million pixels, dimensions at 640, and PDF execution at ten seconds with a 5 MiB output cap. Derivatives retain the source-key hash and daily cache key, with a separate receipt namespace. Cached response reads are bounded at 5 MiB. Renderer startup failure now clears its timeout. No business or financial state changes are introduced.

Review checked authorization before storage access, immutable metadata, source/cache/output bounds, private binary HTTP handling, unchanged document preview behavior, signed-link fallback, ID encoding, controlled disclosure and retries, safe text rendering, multiple receipt timelines, matched invoice links, RTL, keyboard access and mobile overflow.
