## Delivered behavior

The shared `FileUpload` component provides a dashed drop zone with a native keyboard browse control, selected file names/sizes, removal and independent progress bars. It supports configured file counts and announces transfer state through a polite live region. Persian/English messages identify unsupported types, size limits, empty files, excessive counts and invalid names. Rejected selections preserve an accepted draft. Explicit incorrect MIME types are rejected; absent browser MIME metadata is inferred only from the permitted extension/MIME mapping, then included in reservation and direct-upload metadata. Current policy changes revalidate accepted files before submission.

Authenticated `GET /api/upload/policy/:category` exposes only effective category formats and size bounds. It uses the existing resolver, combining current administrator policy with deployment constraints, and neither reserves a file nor grants record authority. Invalid categories fail before policy access; unavailable policy disables selection with a retry control. Real migrated HTTP tests verify both operating contexts, unauthenticated rejection and a narrowed administrator policy that also rejects an oversized reservation. Document forms retain the domain's 50 MB upper bound when a category policy permits more.

Document uploads show actual cross-origin transfer bytes separately from server confirmation. Pause aborts the active request while retaining the selected file, reservation and confirmation key. Resume reuses them: multipart transfers consult existing completed provider parts, and completed byte transfers retry confirmation without sending bytes again. A lost write-once response can receive 412 before the existing server byte verification confirms the owned file. Failed storage requests preserve retryable drafts; account API denial clears private file/reservation state. Scope changes and closing abort work, and obsolete acknowledgments cannot deliver success to a new form.

Cross-origin XHR uses no credentials and only supplied storage headers. Same-origin storage retains fetch with `credentials: 'omit'`, reporting transfer start/completion rather than incremental browser progress. Existing CSRF, step-up verification, profile/business-record associations, replacement history and confirmation audits remain enforced. No new dependencies, schema changes or budget increases are required.
