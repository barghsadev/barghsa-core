# CRM editor form validation, October 3, 2026

## Scope and result

This batch adopts the shared form state, validation, server error mapping and submission guards in `07-ui-ux-design.md#T-07.10.01.02`, `07-ui-ux-design.md#T-07.10.01.04`, `07-ui-ux-design.md#T-07.10.01.05` and `07-ui-ux-design.md#T-07.10.01.06` across CRM profile contact/title, company/representative and address editing together. These global criteria remain open for forms outside this batch.

All three editors keep their typed drafts in React Hook Form through the existing shared binding hook. Zod validates touched fields, revalidates corrections and focuses an invalid field before confirmation. Existing Persian/English messages link to their controls. Contact rules match the API's email/mobile formats and request length limits; company fields reuse the existing changed-only validation, with Zod email validation matching the API. Unchanged historical company fields and geography remain editable even when the current reference catalogue is unavailable or retired.

A shared action-field-error hook accepts only public identifiers owned by the editor and supplies localized messages through `setServerFieldErrors`. On an acknowledged structured 400 input error, the confirmation closes, the editor unlocks, all drafts remain, and focus returns to the invalid control. Unknown/protected identifiers, other errors, conflicts and failed receipts keep generic or existing localized feedback in a top-of-form Alert. The shared confirmation retains its synchronous duplicate-write lock, CSRF, current action/mounted guards, password/OTP verification, rate limits and verified retries; its disabled submit button announces busy state and shows a reduced-motion-aware spinner.

The existing CRM update endpoint now supplies safe optional `error.fields` metadata through `InputFieldException`, with exact request-path whitelists excluding identities, row/version identifiers and database details. Legal reference failures map to the correct official/representative fields. Current authorization, CSRF, step-up, profile/version locks, transactions and audit writes remain. No schema, migration or dependency changes.

Review also strengthens basic contact receipts: profile identity, title, normalized contact values and a valid timestamp must match the captured command. Session headers/timestamps stay on one line inside the existing keyboard scroll region. Header top padding keeps the font bounds inside the cells, repairing the English Axe failures without filtering incomplete findings. Starting a contact edit opens Details; keeping its controls mounted across tab changes preserves the draft, and Save returns to Details before validation.
