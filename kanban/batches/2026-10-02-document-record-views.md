## Delivered behavior

Customer and staff document workspaces now provide table/card layouts, using the existing responsive, account-scoped view preference. Standalone and embedded record workspaces share the same rows. Each file has an icon, isolated filename, human-readable localized size, account-timezone upload timestamp, uploader/category/record metadata and a meaningful state badge. The nine states use semantic colors and decorative icons, including reduced-motion-safe pending-scan pulse, rejection reason, quarantine warning and removed strikethrough. Unknown states receive a neutral fallback; customer views exclude removed records.

Image and first-page PDF thumbnails load lazily through the existing authorized preview endpoint. Supported readable files offer the existing download endpoint; unavailable/uploading/scanning/quarantined files cannot request their bytes. Staff retain authorized clean removed-file downloads, without previews. URL protocols and embedded credentials are validated; external file links use no-referrer/noopener/noreferrer. The signed preview and download receipts survive layout changes and expire within the server lifetime capped at 300 seconds. Temporary errors and broken derivatives can be retried independently.

Accepted revision/state changes discard old receipts and abort obsolete requests. Denial aborts competing reads so late responses cannot restore a link; account denial also discards other cached document URLs. Scope unmount aborts reads. Layout changes do not repeat list/detail/file requests or discard selected reviews, upload files or recovery work. Existing cursor, URL selection, retained-page recovery, review step-up and immutable uploads remain intact.

Quarantined list/detail views show the localized replacement message and suppress raw scanner notes, including customer history. The API’s shared list/detail projection redacts quarantine rejection reasons and review comments. Reads enforce the scan verdict as well as the lifecycle status: replacing a quarantined contract original cannot restore its preview/download or expose scanner notes when the old row becomes Superseded. Real migrated HTTP regressions cover a valid audited legacy transition and a sealed contract replacement, verifying redacted fields and blocked old bytes while the new file remains readable.

CI run `36970984341` for `143355ffa3836362b83e6306328a62626add1b0f` exposed the missing standard timestamp trigger on `conversation_identities`. New migration `0235_conversation_identity_timestamps` attaches the existing `modify_updated_at` function and preserves explicit writer timestamps. It changes no identity rows or historical migration checksums. Drizzle generates the matching snapshot/journal; the new timestamp is monotonic. Upgrade tests cover both pre-identity and populated identity databases, reruns, preserved rows/history and raw/explicit timestamps. The existing foundation invariant remains enforced.
