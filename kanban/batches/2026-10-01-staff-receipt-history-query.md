Confirmed/Rejected state and exact invoice selections combine with submission search/order, half-open submission date ranges and inclusive exact IRR amount bounds. The default remains newest first. Both directions compare and order by the same timestamp/UUID tuple, preserve PostgreSQL microsecond cursors and return at most 25 rows. Bound SQL values and allowlisted directions retain the current live invoice-receipt staff permission and curated response fields. Unknown, repeated or malformed query fields fail before reads. No financial posting, database migrations or per-row evidence reads are introduced. OpenAPI describes new query values and selected-order pagination.

The staff history reuses the shared filter drawer. Search, order, date and amount edits commit in one Apply, including the last uncommitted text input; Cancel discards drafts and invalid amount ranges keep the drawer open. Existing immediate status and explicit invoice Apply controls remain available. Applied search/state/date/amount/invoice chips can be removed independently, and Clear removes filters while retaining order. Exact amount strings survive router serialization, reload and Back. The existing shared cursor hook replaces duplicate local pagination logic, detects repeated cursors and preserves exact failed-page Retry. Criteria-scoped accepted rows and abort guards keep obsolete pages out of another search. Filter controls preserve keyboard focus. Pending queue, reviewed history and invoice ledger query namespaces remain independent; account table/card preferences and historic detail behavior are preserved. Both languages and themes use existing translations.
