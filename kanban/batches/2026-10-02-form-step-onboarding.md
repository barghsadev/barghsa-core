# FormStep and onboarding form state, October 2, 2026

## Scope and result

This related personal/company batch builds the shared `FormStep` in `07-ui-ux-design.md#T-07.10.02.02` and adopts it in both onboarding wizards. Next calls React Hook Form validation for the current stage's named fields. Empty instructions/upload-review stages skip scoped validation; final Submit uses the full schema, returns to the first invalid stage and focuses an enabled control. One form/provider persists across stages. All onboarding text, geography, date and verified document metadata now live in that form's partial draft. Existing localized field rules feed Zod; independent React field/error stores and duplicated synchronous stage validation are removed.

The component keeps schema input/output types distinct, locks Next and Submit before asynchronous validation, retains values after failed saves, and prevents an obsolete step/value/reset/unmount from invoking navigation or submission callbacks. Public subscriptions and methods supply these guards; no private React Hook Form state is used. Native control refs and error descriptions cover the optional personal title, company province/date control and existing fields. Current-stage feedback is visible, and edited invalid/touched fields revalidate. Unchanged representative fields do not repeat validation during a grouped update.

The existing server draft version, authorized catalogue reads, city cancellation/retry, confirmed upload receipts, five-document bound, autosave/reload/conflict recovery, URL/history navigation, departure protection, final receipt verification and combined profile setup remain in their established handlers. Upload files and transaction/network state remain separate from saved form values. Draft/API formats and user-facing dictionary messages remain compatible.

Shared component criteria are implemented with actual wizard adoption. React Hook Form adoption in simple/advanced electricity, saving and solar remains the next related batch; global form-system adoption and other epic criteria remain open. No scheduler, external supervisor state/handoff, historical `kanban/loop-state.json`, or generated completion/event history is changed.
