# Team invitation and role form validation, October 3, 2026

## Scope and result

This batch adopts `07-ui-ux-design.md#T-07.10.01.02`, `.01.04`, `.01.05` and `.01.06` together across customer team invitations and both member-role editors. These global form criteria remain open for the other product forms.

Invitations now retain username, role and optional note in the existing shared React Hook Form/Zod binding. Destination validation reuses the API's username normalizer. Touched-field correction, bounded messages, linked localized errors, first-invalid-field focus and a top-of-form failure Alert preserve the draft through field, conflict, network and invalid-receipt failures. A synchronous lock covers validation and submission; controls cannot cancel a pending write, the submit button announces busy state, and its spinner respects reduced motion. The dialog scrolls within the mobile viewport. Only a valid creation receipt clears the draft and restores trigger focus.

Inline and detail role editors share one controlled role-group form. At least one permitted role is required; duplicates are rejected. Confirmation retains the existing captured command, password/OTP verification, CSRF, retry and exact-role receipt checks. A structured role error closes confirmation, retains the choices and focuses the group with localized feedback. Saved-role changes still require explicit reset; unchanged, owner, stale and denied commands remain blocked. Live command guards prevent asynchronous validation from opening a review after the editor becomes unavailable. Fixed role checkboxes are not a dynamic permission array; that separate criterion remains open.

Invitation and role endpoints supply additive public `error.fields` metadata through the existing `InputFieldException`. Whitelists exclude submitted values, recipient information, identities and database details. Unknown metadata stays a form-level failure. Existing authorization, current session/step-up, transaction locks, session revocation, audits and rollback behavior remain. No schema, migration or dependency changes.
