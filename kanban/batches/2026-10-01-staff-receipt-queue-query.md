## Delivered

Both pending queues now support literal receipt/profile ID, bank name and payer reference searches; invoice receipts also search invoice IDs. Search is trimmed, bounded to 120 characters and rejects control characters. Only oldest/newest submission orders are accepted, with the existing oldest-first operational default. Reads return at most 25 receipts plus a nullable cursor. Timestamp/UUID comparisons and ordering use the same direction, preserve PostgreSQL microseconds and resolve ties without duplicate pages. Wallet results exclude synthetic credit rows. Existing live wallet/invoice staff permissions remain separate. Query values are bound, SQL sort/comparison use fixed constants, and no financial writes or migrations are added.

The shared toolbar debounces search once at 300 ms, offers submission order and Clear, and wraps on mobile. Pagination uses exact opaque cursors, detects repeated cursors and keeps the requested cursor during Retry. URL search, sort and page survive reload and Back; invoice pending criteria are independent of ledger and reviewed-receipt history criteria. Existing account table/card preferences and exact amounts/dates remain intact. Refresh within the same wallet queue retains valid invoice/rejection drafts; changing queue criteria clears selected pending work, drafts and open approval dialogs. History selections remain independent. Old requests cannot repopulate another queue, and late review/dialog callbacks cannot restore obsolete approval work, including reopening the same receipt. Access loss clears retained private data. Both languages have search guidance. OpenAPI documents query fields, the 25-row page and validation errors.
