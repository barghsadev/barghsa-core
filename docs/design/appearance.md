# Published appearance and motion

Branding uses the existing `/api/admin/branding/config` draft editor and explicit activation, with public reads from `/api/public/branding/config`. Every saved revision is immutable. Current permission, step-up, version checks, serialization and audit remain authoritative. Draft previews stay private and cannot publish assets or change another user's appearance.

`primaryColor`, `secondaryColor` and `accentColor` define light fills. Optional `darkPrimaryColor`, `darkSecondaryColor` and `darkAccentColor` define dark fills. An older revision without those fields retains its existing colors in both modes. Foreground colors use the higher WCAG contrast ratio. Primary text falls back to the readable semantic foreground where the chosen color would fail against a page/card surface; the editor explains this adjustment before publication. Background validation still rejects unreadable page text. Default dark surfaces and foregrounds avoid pure black/white; validated custom brand colors retain the administrator's choice.

`logoUrl` is the light logo and `logoDarkUrl` is an optional dark alternative. Missing dark logos fall back to the light logo. All uploaded variants and favicons use the same verified, sealed `branding_logo` boundary. Same-origin URLs retain the owner's accepted private/no-store design. Only an active revision makes its referenced assets publicly readable; draft reads require staff authority. No CDN or new storage lifecycle is introduced.

The editor shows current and local draft previews together, including colors, typography, numeral style and the selected theme's logo. These previews replace a separate temporary global-theme button: they remain visible while editing and leave the active application's published tokens intact. A captured save/activation accepts only its matching revision, config and canonical asset receipt. A changed authority or foreign revision closes the captured action and requires explicit recovery.

The native theme selector in the topbar account menu offers light, dark and device modes, with an icon for the resolved appearance. An explicit published policy wins; otherwise a saved account/browser preference wins over the device. Writes remain server-confirmed. Existing `barghsa.theme.v1` and `barghsa.theme-policy.v1` storage keys and the nonce-bound blocking SPA head script remain. This is the approved Vite client architecture, with no server-rendered cookie middleware. Brand titles remain bilingual, favicons follow the published revision, and cold read failures keep a usable default identity. Later failures retain the last validated brand.

The selected navigation link changes its foreground and background together when the theme changes. The previous background would leave the new text unreadable during a transition.

Email branding uses the same active revision and validates every color/asset again. A fixed theme chooses its corresponding palette and logo. System policy emits a readable inline light fallback and a trusted dark-media stylesheet with both logo variants for supporting clients. Clients that strip media styles retain the inline fallback. Authored template content stays escaped/restricted and staff previews remain sandboxed without script or navigation authority.

`Animated` and `useReducedMotion` live in the shared UI package. Fade, slide, scale, shimmer and page variants use CSS; no animation library is added. Route replay uses native animation state and never keys/remounts business children. Page transitions last 200ms with a 20px translation. Content starts readable, and transforms leave layout geometry unchanged. Lists and dashboard cards use bounded short staggering. Button/card micro-interactions, native switch/accordion/progress behavior and directional toast entry share the motion preference.

Reduced motion removes entrance, hover, shimmer and toast transitions before React mounts and responds live thereafter. Essential spinners slow to two seconds and progress width changes slow to 600ms. Semantic direction mirroring and checked switch positions remain intact. Printing forces light surfaces/text and stops animations without rewriting the user's saved theme.

Browser checks normally use the existing five Playwright projects. Set `BARGHSA_DESKTOP_CHANNELS=1` to enable explicit `chrome-stable` and `edge-stable` checks. An optional local `BARGHSA_EDGE_EXECUTABLE` can identify a verified external test executable. Ordinary matrices do not depend on an additional globally installed browser. Execution receipts record the actual tested browser/version; engine coverage does not claim an unrun branded channel.
