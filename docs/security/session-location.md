# Approximate session location

Settings → Security displays an approximate country for each session, derived from the IP already recorded by the server. The API returns only `location.countryCode` or `null`. The browser localizes the country name in Persian or English and labels it as an estimate. Unknown, private, loopback and documentation addresses display an unavailable result. A country estimate does not establish someone's physical location and never influences authentication, permissions or device trust.

Lookups use the packaged IPv4/IPv6 data in `geoip-country@5.0.202609050122`. The lookup runs locally and sends no IP addresses to a service. No database migration or additional per-session location storage is needed. The package and its data are pinned by the workspace lockfile and included in the API deployment. Country granularity keeps the database around 8 MB; this feature does not claim city-level accuracy.

The data includes GeoLite2 country data created by [MaxMind](https://www.maxmind.com/). [Package documentation](https://github.com/sapics/geoip-country) describes the lookup and data updates. The upstream README directs new development toward its successor, while this pinned package supplies current bundled data and supports the project's Node 20+ development range. The current `geoip-lite` release requires Node 24; it was not installed by weakening engine checks. The September 13 R05 review retains this exact parser for this display-only feature. Its parser is unmaintained; new bundled data releases do not change that status. Retaining it does not authorize new lookup consumers or use in any access decision.

Refresh country data through a reviewed package/data update and rebuild the API image. Confirm the package's data terms and update procedure during deployment preparation. Do not invoke its updater from a request handler or use location as evidence for account recovery. Local checks verify the packaged lookup, HTTP response and UI behavior; they do not certify future database freshness or deployed proxy IP configuration.

## Maintenance disposition (September 13, 2026)

The application imports only `lookup`; its declaration exposes no updater or watcher. Input is a server-recorded string of at most 45 characters, validated by Node's IP parser. Output is restricted to a two-letter country code or unavailable. Runtime lookups read the bundled binary data in memory. The package's updater can spawn a child process, but the application does not import or call it. Never supply request-controlled data directories, command-line settings or update options. Preserve the default packaged data directory in the API image.

The proposed successor is a separate parser/configuration change, not a transparent data update. Keep that migration outside these confirmed repairs until its offline startup, Node support, country-only data size and IPv4/IPv6 behavior have been checked. No scheduled maintenance job or production data update was created here.

Before each production release, the release operator checks the upstream maintenance notice, package/data version and integrity in the lockfile. A data update uses an exact reviewed package version in `apps/api/package.json`, regenerates the lockfile and runs a frozen install. Review the package diff for runtime/updater changes; do not accept a data refresh as evidence that the parser is supported. Run the session-location unit and session HTTP checks, build a self-contained API artifact, and verify IPv4, IPv6, mapped IPv4 and unavailable/private ranges from that artifact. Record the package version and hashes of its three bundled data files in the release evidence, then rebuild and deploy the API image through the normal release process. Roll back the complete image and lockfile together if lookups regress.

If the pinned parser has a confirmed applicable defect or no acceptable dataset can be packaged, disable the optional location display or review a replacement before release. Do not silently substitute a remote lookup service or use stale location as recovery evidence. Actual freshness checks and image rollout remain release operations; local acceptance does not certify them.
