# Authentication workspaces

Public authentication uses its separate entry bundle and brand/form layout. Before displaying an authentication form, the router checks the current session. A signed-in visitor enters through `/app`, which retains the existing role, terms and profile/onboarding gates. Auth pages render no authenticated workspace data. The public terms and recovery-support pages remain available independently.

The owner approved retaining local zxcvbn on 2026-11-06. Its raw scores drive five localized display labels and improvement hints. Four colored segments supplement the accessible numeric estimate. Predictable patterns remain weak under the existing estimator; the character-class heuristic in the older UI wording is not used. No password reaches a strength API. New meter feedback loads with the existing interaction-only estimator; public-history translations stay with the terms route so authentication keeps its original payload budget. The meter is informational and does not replace or strengthen the backend's minimum-password validation. Its feedback stays visible while a value remains, and reserved space plus reduced-motion-aware transitions preserve form control positions.

Login, registration and password recovery retain their existing captured form submissions, current CSRF, OTP, expiry, cooldown and uncertain-result boundaries. A required password change remains an owned stage in the login layout, before a session is issued. It requires confirmation, clears credentials on an accepted result and returns to login. Unknown results do not replay a potentially consumed OTP, password-change grant or reset token. Conditional delivery messages do not claim that a matching account exists or that a provider accepted an SMS.

The public terms page now offers published-version history. Its paginated endpoint returns only immutable version IDs, public version labels and publication times. Draft and unknown cursors behave alike and cannot seek into the published list. Historical links request the exact published version. Following or viewing one records no consent. A failed history page preserves the current document and earlier history entries for an explicit retry. Existing consent checks still require the exact current version and current session; history access grants no business or administrative permission.

Test fixtures for public auth screens now identify the initial session as anonymous. Existing workspace fixtures own the subsequent successful sign-in handoff. Separate browser cases verify that an already authenticated visitor leaves each auth screen before any form appears.
