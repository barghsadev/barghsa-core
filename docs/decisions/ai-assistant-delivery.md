# AI assistant delivery

Launch AI answers use published knowledge within the current slot, audience, session and profile boundaries. Profile-data tools, business tools, AI-proposed writes and trusted-UI approval cards remain explicitly deferred by the owner's read-only launch decision. Ordinary application confirmation dialogs do not implement those future AI controls. Contextual question suggestions describe the supported knowledge scope.

The customer assistant requests SSE on the existing authenticated questions endpoint. The server completes inference, output-policy evaluation, source eligibility, current authority and the required audit before constructing the stream. It then delivers the approved answer as Unicode-safe text chunks followed by the complete answer receipt. It adds no artificial typing delay. Provider output is buffered until these checks pass, so streaming does not reduce the wait for the first text. The endpoint retains JSON for existing clients and rolling deployments. Both transports use the same request identity, quota, cached answer and replay authorization.

The UI shows received text progressively with an incomplete-answer notice. It accepts the answer only after a matching final receipt and clean stream completion. Interrupted, malformed, oversized or mismatched streams retain the captured question and request ID for retry. A scope change aborts the stream and clears private history. Received-time labels for incomplete text remain distinct from the server's final answer time. Sources and policy metadata appear only with the accepted receipt.

The assistant's explicit account-status button uses the ordinary authorized dashboard read. It labels that result as a direct account receipt and never sends it to the model. Wallet and invoice fields follow their current read grants, and a switched-profile response is refused. This does not enable a model profile-data tool.

Admin test conversations use their own session-owned records, bounded history and request receipts. The agent selector includes inactive drafts as disabled entries; current validation and the backend both refuse their use for inference. Test conversations do not alter customer or staff conversations or perform business writes. They remain subject to actual model budgets, a database-enforced ten-request-per-admin minute limit, current source and permission checks, redaction and marked `admin_test_chat` entries in the append-only security audit. The UI specification's former exclusion of all AI audit logs conflicted with the AI safety requirements; security audit records remain mandatory. Clearing the visible test conversation clears its UI history, not audit evidence.

Source excerpts, policy outcomes, token usage and latency are server metadata. Unknown historical values remain unavailable rather than being estimated. English/Persian input, localized timestamps and numbers, composition-safe Enter handling, separate newline input and bounded textarea resizing apply to both chat interfaces.
