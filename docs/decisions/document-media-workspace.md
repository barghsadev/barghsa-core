# Document and media workspace

The shared upload control reads the current category policy. It shows allowed extensions, the size limit and file count before selection, then validates each filename, declared MIME and size. A rejected selection preserves the accepted draft. Missing browser MIME metadata uses the configured extension mapping; the server still verifies the actual stored bytes before sealing or trusted use. This retains the approved two-stage upload boundary.

The browse control is keyboard accessible and also accepts dropped files. Selected files show names, sizes, previews and individual progress. Progress announcements distinguish transfer, confirmation, pause and failure. A paused or uncertain attempt retains its reservation, exact file and confirmation key. Confirmation retries do not create another document or repeat an already acknowledged storage transfer.

Inline previews contain images. Selected PDFs use the authenticated, CSRF-protected transient renderer, bounded to 10 MiB of PDF input and 5 MiB of PNG output. It persists no selected document. Stored PDFs use authorized first-page image derivatives. Original PDF bytes remain on the explicit download path. Unsupported or failed previews show a document icon, and aborting or replacing a selection revokes its local object URL. Preview failure does not remove an independently authorized download.

Customer and staff document lists share metadata and file actions in table and mobile card layouts. Each row shows the category icon, filename, localized size and upload date, document state and current permitted actions. File links load only on request and remain bound to the accepted revision, state and permission projection. Layout changes preserve open work. Current account or profile changes clear private work, and denied reads clear stale links and actions.

Document states use labels and icons alongside semantic colors. Rejected files show the review reason. Quarantined files show only the safe replacement message, including when a superseded document has a quarantined scan state. The server redacts scanner reasoning from the customer projection and event history, and the UI suppresses it again. Quarantine blocks preview and download; a cached derivative does not bypass current authorization.

Replacement creates a successor while retaining the original history and exact business association. Contract version and role remain bound to the replacement. Current server permissions determine replacement and removal controls, including service-specific restrictions. A remove action changes document visibility; it does not authorize physical destruction. Financial and contractual bytes remain permanently retained under the owner's approved policy. Other destruction continues to require the existing retention, legal approval, hold and retry checks.
